# 错片入库恢复：以《吞噬星空》E247 为例

本流程适用于 **Reelay 已将错误的分享文件记录为某个单集成功入库** 的情况。不会自动删除、覆盖、移动或复制用户网盘文件。生产操作前请先备份 Reelay 数据库，保存相关任务 ID、远端文件 ID 和来源核验记录。

## 可观察到的故障

- 入库任务：`吞噬星空 (2020) S01E247`，结果文件约 4.04 GB
- 分享根目录：`247 4K.mp4`，约 1.62 GB
- 旁支目录：`洛DA/4K.mp4`，约 4.04 GB

文件大小相符**不等于**内容相同。必须在网页「任务详情 → 实际转存来源核验」检查真实 source ID、share_path 和 size，并人工播放核对内容。

## 恢复顺序（不要互换）

1. **暂停自动重复处理**：不要重新粘贴相同链接，也不要删除转存任务。
2. 在「任务列表」找到状态「已入库」的 E247，进入详情，查看「实际转存来源核验」。如果选中源为旁支目录的 `4K.mp4`，且确认不是目标动画，填写原因并点击 **「标记错片并暂停自动转存」**。
   - 此操作仅撤回**这一任务自己的**内容/分享去重声明，将 E247 加入自动转存隔离列表；不改动网盘文件。
   - 若按钮不可见，可能并非单集/单文件已核验任务，或当前部署版本不支持。**不要直接操作数据库或强制重试。**
3. 在阿里云盘中人工确认错误文件内容，把错误的 `吞噬星空 - S01E247 - ...mp4` **移至单独待核对目录**并留存其文件 ID。先移动，**不删除**。与旧的 E01–E246 等文件分开。
4. 人工打开分享中的 `247 4K.mp4`（约 1.62 GB）核对片头/内容；不能仅看文件名推断它是真 E247。
5. 回到 E247 已隔离任务详情，确认第 3 步已处理，点击 **「人工处理完成，解除隔离」**，按界面提示输入：`我已核对并处理错片`。
6. 通过「立即转存已有分享」重新建一个**新任务**。本次选择 **「分享根目录（仅当前层）」**，在预览中确认只选 `247 4K.mp4`、该来源文件 ID 和大小。目录选择绝不是保存目标目录的配置。
7. 转存结束后到阿里云盘人工确认新 E247 位置、大小和视频内容，然后重新进入订阅列表查看 E247 已登记。错误文件仍在待核对目录，确认无其他用途以后再考虑如何处置。

## 阻止以下风险

- **不**用「更改识别结果」直接把原 4.04 GB 的错片重命名成正确 E247。
- **不**在隔离尚未完成时重新转存 E247，避免失效的错误台账影响重复判断。
- **不**覆盖原 E247 文件、批量清理目录或清除整个库的去重记录。
- 分享同时包含明确 E247 和其他目录无集号 `4K.mp4` 时，系统必须先选择分享源文件夹，不得由 AI 推断 `4K.mp4` 也是 E247。
- 「关联旧集」是用于无 Reelay 转存记录的历史真实视频，**不是**错片任务的替代隔离操作。

## 订阅列表的数据含义

- **Reelay 已登记**：仅代表有完整核验的转存去重台账，不是对当前云盘中文件内容的持续播放审核。
- **尚未登记**：当前没有这条可信 Reelay 转存记录，**不能证明**云盘中该集不存在；网盘索引中的历史文件另行标明候选。
- **错片隔离中**：该集不计入已登记，自动转存暂停，必须先人工核对后再解除。

这套操作与 Reelay 的 GitHub 模拟 E2E 不会操作用户真实阿里云盘；真实账号测试需在有明确授权的环境中单独核实。
