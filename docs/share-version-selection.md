# 同一分享中有 HDR.Vivid / DoVi 等多个版本

例如阿里云盘分享中有两个目录：

- `Season 1 (HDR.Vivid)`
- `Season 1 (DoVi)`

这不是简单的“两个分辨率”：HDR.Vivid 与 DoVi（Dolby Vision）是不同 HDR 标准。选哪个由播放设备支持、用户偏好和实际片源决定，**Reelay 不根据名字擅自择优**。

## 处理步骤

1. 在 **待审批** 或 **任务列表**中打开对应资源的**任务详情**。
2. 点击 **选择分享版本 → 读取分享文件夹**。
3. 预览网盘只读枚举到的文件夹、视频数量及识别到的集数。
4. 在下拉框中选 `Season 1 (DoVi)` 或 `Season 1 (HDR.Vivid)`，点击 **确认这个版本**。默认“此分享链接以后沿用该版本”，可以取消勾选。
5. 若任务已失败、且未形成转存检查点，点击 **重试**；若仍待审批，点击 **确认转存**。系统之后只从指定分享文件夹挑选视频，不会从另一个版本填补缺集。

只有失败/待人工/待审批且**尚未发送云端复制、没有转存清单及已落地文件**的任务允许更改。正在转存、结果不明、已入库的任务不能切换分享文件夹后重新发送。

## 安全边界

- 文件夹选择使用**分享源文件夹 ID**（并核验根目录名称），不是保存到网盘中的目标目录，**不会修改保存目录**。
- 每次正式转存都重新读取真实分享文件：指定 ID 不存在、根目录重命名、不可读取或缺少明确宣布的最新集数，均停止并请求人工确认。
- 一个版本目录内仍有同集多个文件时，仍需人工核对，不自动覆盖或混合。
- 已转存的文件继续遵循 Reelay 的内容去重规则；选择另一个版本**不会自动洗版**。
- 如果数据库说 S04E013 已入库，但云盘最终目录实际只到 E12，打开被跳过的单集任务，点 **强制转存本集**。必须精确选中共享中的 E13 源文件，再选择原阿里云盘 Season 04 最终目录、模式「直接存入」，确认后只允许这一次绕过旧季集去重。原历史回执不删除、不自动覆盖现有文件；发生同集或同名冲突时用安全数字后缀共存。该操作不改变自动订阅的去重规则。
- 针对同一分享记住的选项只在该分享上复用，不根据不同分享链接中的同名目录推断版本。
- 文件夹枚举与选择均为只读；确认转存/重试之后才会走既有的安全转存、远端读回校验流程。
- GitHub Actions 使用模拟网盘和 HTTP/Chromium E2E，不操作真实阿里云盘资源库。

## E247 错片与多层目录的保护

分享中可能同时有根目录 `247 4K.mp4`（约 1.62 GB）和其它目录下的 `4K.mp4`（约 4.04 GB）。两者绝非同一部作品/同一集的可靠证据：

1. 分享列表会显示**完整的目录树**（例如根目录直接视频、子文件夹及空子文件夹），而不只是第一个顶层版本。读取不完整、分页异常或目录过深都会报错，不会当作已完整扫描。
2. 根目录直存视频有独立的“分享根目录（仅当前层）”选项。**选这个只取根目录的文件**，不包含旁边其它电影文件夹的 `4K.mp4`。
3. 识别到有集号文件与不同文件夹的无集号视频混杂时，禁止 AI 把 `4K.mp4` 随意指认为 E247；必须先选具体文件夹。目标文件夹仍没有集号则停止，不得静默重命名后当作正确剧集。
4. 选中的父文件夹仍含两个同集 HDR 版本时，需进一步选到具体子文件夹；界面展示文件数量、样例文件名/大小。
5. 完成转存后的任务详情有“**实际转存来源核验**”，显示当时来源文件的原名、来源相对路径、原始大小、当时映射的季集。**落地成功不是内容正确的证明**。
6. 已出现错片时，在已入库任务中填写原因，点击“**标记错片并暂停自动转存**”。它会保留原任务和回执、单独备份去重键证据、撤销这条任务自己的错误去重声明，并拦截该作品该季集的自动转存。**不会移动、删除、改名或重复转存任何真实网盘文件**。
7. 人工在云盘核实、移走或整理错片后，可以输入确认语解除隔离。错误的旧去重键不恢复；随后必须选择能从源文件名正确识别 E247 的来源，再手动继续。不要在旧错误文件仍留在目标目录时放任自动转存。

上述测试全部使用内存数据库、模拟云盘与 Chromium；没有访问或更改用户的真实网盘内容。
