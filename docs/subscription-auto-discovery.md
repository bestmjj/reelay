# 主动追剧与订阅模拟测试

Reelay 现在可以利用**已经登录的个人 Telegram 会话**，对已经配置的监听来源做定期、有限量的历史搜索。
不需要新账号、第三方爬虫或另外的资源网站。对于只配置了 \`@shareAliyun\` 的部署，它就是唯一的检索来源。

## 一次性配置

在 **设置 → 监听来源 → @shareAliyun** 检查：

- **确认方式：人工确认**。不在订阅中的作品继续待审批，而不会因为来源发了新消息就全部自动复制。
- **转存方式：规则 + 订阅放行（subscription）**，只有已经订阅且确认是新集的作品可以绕过人工批准。
- **识别方式：AI 或规则**。TMDB 规范片名、季集数、置信度、过滤规则、分享清单和内容去重仍会逐项检查。
- **存储网盘：阿里云盘**，并选择属于阿里云盘资源库的保存目录（可以配置成来源兜底目录）。
- **追剧订阅** 中的作品要启用「新集自动转存」，没有标记已完结。

**结果：** Telegram 实时消息仍立即进入 Reelay；在没有新事件时，后台还会定期查询同一来源内这批订阅的最近分享消息。符合条件的资源继续走既有的持久化转存、校验、去重与失败重试流程。无法确定的消息保持待审批或失败状态，供人工纠正。

## 主动发现机制

- 每 **30 分钟**运行一次定期搜索（实时消息不需要等待）；一次至多查询 30 组「频道 × 正在自动转存的订阅」，按照**最久未检查的先处理**。多来源时不会永远只查第一个频道。
- 每次 Telegram 查询至多查看最近 12 条搜索结果；每部剧至多提交 4 个包含有效网盘链接的候选到原来的消息接收队列。
- 首次启用回看**最多 24 小时**，并且不会扫描订阅创建之前的消息，避免把旧季全集突然批量转存。日后按上次成功检查时间增量补查，允许 1 小时重叠以补漏，但最长不超过 7 天。
- 搜索只访问已配置、当前个人会话**有权限读取**的 Telegram 频道或 Bot；不会绕过访问控制、搜索未配置频道，也不会猜测或加入新频道。
- Telegram 搜索有内建限制，遇到 FloodWait 自动保存冷却截止时间；其他错误独立记录，下次恢复后重试。所有搜索间隔至少 2 秒。
- 已接收消息依然使用 Reelay 的 **来源 + 消息 ID** 持久化去重；真正转存时继续使用保存/内容级去重。进程重启或重复搜索不应重新建立同一条消息任务。
- 原有的实时监听与断线启动补拉保持不变。如果 Telegram 不允许访问频道历史或搜索不到新消息，不能保证发现该来源没有发布的资源。

## 专用模拟测试

打开 **追剧订阅 → 目标作品 → 模拟测试**。

1. 可以直接按「开始模拟测试」，系统从已经接收到的消息中选取这一部剧的最近匹配消息。
2. 如果还没有接收到相关消息，可以粘贴一条真实频道消息（包括分享链接）再测试。
3. 页面展示识别片名、季集、是否命中对应订阅、自动放行或待审批、目标网盘和**预计**目录，以及决策轨迹。

模拟测试不写入任务表，不触发转存、不修改订阅与去重记录、不会操作网盘；但识别过程中可能调用已配置的 AI/TMDB API。模拟结果也不证明分享链接当前有效、目标文件未存在或真实复制一定成功。

实际运行时点击追剧列表「**刷新检索状态**」，可以查看最近检索时间、候选数量或 Telegram 错误。只有部署了本分支并运行了 worker 主进程后才会有真实检索记录。

## 何时需要人工干预

- **尚无匹配样例**：说明 Reelay 尚未收到适合模拟的频道消息；后台继续自动检索。需要确认时可以粘贴真实消息。
- **未匹配订阅**：检查 TMDB 规范条目、片名别名、季集识别，而不是直接放行所有资源。
- **需要人工处理**：低置信度、TMDB 匹配不足、跨季合集、缺季集或过滤规则不满足。
- **目标网盘不匹配**：来源里选择阿里云盘，但消息实际包含 115 分享（或相反），需要调整来源/转存规则。
- **分享失效、云盘账号失效、转存结果不明**：原有任务状态、重试与只读复核负责恢复，无法安全自动恢复时转人工。


## 已有云盘文件复用与去重

旧视频先到「媒体库 → 扫描已配置目录」完成分批扫描（扫描未完成时继续扫描）。
系统把扫描到的文件保存成独立只读索引；只有可信的作品身份和文件当前仍真实存在时，才避免再次转存，不把扫描观察假装成 Reelay 已完成任务。

对没有 TMDB 标记的老文件，在「追剧订阅」该作品行点击 **「关联旧集」**：
1. 按当前订阅的片名与季号预览历史文件，每页最多 50 个，显示目录、文件名、集数、是否关联。
2. 确认某些视频确实属于当前 TMDB 作品后勾选它们，点击 **「确认关联」**。
3. Reelay 再次通过已登录网盘的文件 ID 查询真实位置、名称、大小和可得哈希；任何一项变化都拒绝关联。关联只写本地的媒体身份映射，不移动、下载、转存、删除、覆盖任何网盘文件。
4. 后续转存同一集时再次进行只读网盘核验。文件被改名、移动、离线或索引已过期会转人工确认；不能凭关联记录直接认定已转存成功。重新扫描后可重新关联。
5. 如果旧文件很多，按页分批关联；无需逐集重复提交分享链接。

现有文件的分类移动和重命名在 **工具 → 网盘目录** 中完成：目前只允许**同网盘单个文件**移入已有目录或修改名称，禁止删除与覆盖。尚未开放大批量不可逆整理；涉及不同作品、格式不明或任务仍在运行的目录，建议先核对再移动。

## 首次订阅从哪一集开始

在「追剧订阅 → 添加订阅」的「最早自动接收集号」填写正整数；已有订阅也可点击行内 **「起始集」** 修改。

- 当前最新已知 E100，填写 **100**：只有 E100 以及之后明确识别的新单集可以自动放行。
- 不需要 E100、只想从下一集开始，填写 **101**。
- 留空：沿用原来的单集自动追更规则，但系统不负责猜测“最新集”，也不主动补历史全集。
- 无法识别季集、合集跨多集或作品不确定时仍要求人工处理。正在执行的任务仍依其接收时的配置快照运行，不会被新增起始集强行改写。

## 历史频道消息立即转存

在「追剧订阅 → 立即转存已有分享」粘贴以下一种内容：

- 已配置且个人 Telegram 账号有权限读取的 **https://t.me/shareAliyun/123456** 一类公开频道消息链接；Reelay 会请求已登录监听进程只读取这一条消息，并取得真实资源分享链接。
- 包含片名、季集、分享链接的频道完整正文。
- 阿里云盘或 115 分享链接；若仅有分享 URL 而无法确定作品，则转人工确认，不会盲目整理。

只有你配置过的频道才允许按 Telegram 消息 ID 读取，不能借此访问其他频道或私有历史消息。用户直接提交的资源使用确定性消息 ID，重复点击不会反复创建相同任务；转存仍由后台执行规则、清单选集、去重和安全验证。该入口只处理本次资源，**不会暗中新增追剧订阅**；需要追更时另外订阅该作品。多季合集或单条消息包含大量旧集时，请仔细确认清单，避免人工提交导致历史资源超额转存。

## 同集来自不同来源

不同来源的同一部剧 E106 不会仅因为文件名、哈希不同就被当作新集。新任务以 TMDB 作品 ID、季、集和**目标网盘身份**生成共享占位，同网盘不同目录与中文/英文不同片名也不能在同一时刻占用同一集；已完成任务与扫描到的可信现有文件会进一步在复制前去重。不同码率/字幕/版本默认只保留已确认版本；升级候选需人工确认，且自动整理的 `no_delete` 默认保持开启。跨不同网盘并不错误互相判作已经保存。

## 诊断总览

控制 Bot 显示「已连接」与通知投递中存在**历史失败**可以同时成立。总览「通知发送」现在显示最近失败投递的类型、接收渠道、尝试次数与时间，并说明累计失败不代表目前 Bot 断线；可手动重试。追剧模拟测试在本地没有样例时，改为通过已授权监听进程只读搜索频道历史并返回未找到的具体原因；搜索失败不意味着频道没有发布。

## 重要限制

旧云盘里已有的文件**不等于** Reelay 已验证入库的转存记录。主动检索虽有时间窗口与转存去重，仍不能仅靠文件名就绝对排除人工提前保存过的历史文件。第一次正式使用前，建议先核对目标目录和旧文件索引；如果用户已有大量未被 Reelay 记录的旧集，应先验证单集，再逐步扩大自动化范围。

此功能不会搜索互联网或未知 Telegram 频道，不保证全网最快发布，更不保证每条分享仍可用。资源不足时会保留缺集状态，不能凭空生成分享链接。

开发校验：\`python -m unittest tests.test_subscription_discovery tests.test_subscription_simulation tests.test_subscriptions tests.test_source\`，然后执行仓库 \`.github/workflows/ci.yml\` 所列的完整 Python、前端和 Docker 检查。真实 Telegram 搜索和云盘自动转存还需使用有权限的测试账号验收。
