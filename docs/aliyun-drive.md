# 阿里云盘存储和登录

Reelay 支持把 **阿里云盘（Aliyun Drive）分享链接**保存到阿里云盘账号，同时保留原有的 115 网盘支持。
默认存储仍然是 115；升级后不会自动迁移已有任务、目录或凭证。阿里云盘默认使用**资源库／数据盘**，不会把备份盘当作资源库。

## 在管理台登录

1. 进入 **设置 → 网盘连接 → 阿里云盘连接**。
2. 点击「扫码登录阿里云盘」，用手机阿里云盘 App 扫描二维码，并在 App 内确认。
3. 管理台轮询扫码状态；确认后，后端验证获取的 Refresh Token 并安全保存，不返回 Token 原文。
4. 点击「检测并刷新」可主动检验登录；失效时点击「重新扫码登录」即可恢复。
5. 「清除登录」仅删除 Reelay 本地保存的凭证，不删除阿里云盘文件，也不保证远端撤销授权。

扫码接口不可用时，可展开「手动填写 Refresh Token（高级）」粘贴令牌。后端先验证，再保存
**验证时返回的轮换后令牌**；验证失败不会覆盖原来有效的凭证。

二维码会话仅存在服务端内存中，默认 5 分钟过期；登录成功或取消后不再使用。接口要求登录管理台，
扫码轮询使用 POST，受管理台现有同源写入保护；二维码图片从服务端生成 SVG，禁止缓存。

阿里云盘网页扫码采用公开项目使用的 Passport Web 登录流程，不属于稳定承诺的开放平台 OAuth API。
如果官方变更扫码接口、要求额外校验或反机器人策略，可能需要改用手动令牌登录；不要尝试绕过官方风控。

## 选择存储和目录

- 在「设置 → 监听来源」展开目标来源的「高级设置」，把 **存储网盘** 设为 **阿里云盘（aliyun）**，不必修改其他来源或全局默认的 115。
- 在「设置 → 基础 → 保存目录」点击「更换目录」，弹窗中选择 **阿里云盘（资源库）** 后浏览目录。未登录的 115 不会阻止你切换。
- 保存到阿里云盘的目录配置采用 `aliyun:文件ID`（根目录为 `aliyun:0`）；历史 115 数字 CID 保持原样，运行时会检测目录与来源选择的网盘是否一致。
- 同时使用两种网盘时，请为各自的目录创建不同别名（例如「115动漫」和「阿里动漫」），并在各来源中选择正确别名。
- 选择目录后点击页面底部「保存」。无需登录 115 才能运行仅使用阿里云盘的来源，原有 115 任务和目录不自动迁移。

解析器可识别 alipan.com/s/ 与 aliyundrive.com/s/ 的分享链接。一个存储 Provider 只处理对应网盘的分享；
错误匹配会停止处理，而不是把分享码送到另一家云盘 API。

## 令牌失效与中断恢复

- Access Token 到期后由后端使用 Refresh Token 更新，轮换后的 Refresh Token 写入 data/secrets.json。
  多进程重新载入密钥时，按文件修改时间获取最新值。
- 读请求遇到明确的 401 时可刷新凭证并重试一次；对有副作用的转存、移动和删除 **不会自动重发**。
- 转存采用独占的 .reelay-<task_id> 目录。先保存本次计划与接收状态，再发送复制请求。
  请求超时、返回不明确或部分文件落地时，只读取暂存目录核验，不重复复制。
- 已存在的剧集按目标网盘、目录、作品和季集去重；媒体库整理的同名冲突仍采用原配置策略。
- 如果登录时切换为另一阿里云盘账号，或旧转存任务指向备份盘，原任务清单里的 drive_id 会阻止跨账号、跨盘恢复与删除。历史清单缺少 drive_id 时同样拒绝自动恢复，必须人工核对。

**注意：** 这些保护优先避免产生重复文件；它们不能保证任意外部分享的云端复制一定完成。
受网络超时、分享过期或云盘接口限制影响的任务可能需要人工核验、修复登录或补齐内容。

## 开发验证

后端：python -m unittest tests.test_authaliyun tests.test_web_aliyun tests.test_aliyun

完整 CI 按仓库现有配置运行：ruff check .、python -m unittest discover -s tests -v、
python -m reelay.main --dry-run；前端运行 npm run typecheck、npm run lint:eslint、
npm test、npm run build。真实扫码与转存仍需使用受控的个人测试账号单独验收。
